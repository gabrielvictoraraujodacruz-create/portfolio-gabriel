Por dentro dos projetos

O passo a passo de como as partes principais funcionam, em linguagem simples. Construí tudo com o Claude Code; aqui está o que eu preciso entender para explicar, testar e corrigir.

  1. O HTML: uma caixa onde as respostas aparecem e um formulário com um campo de texto.
  2. O evento: quando você aperta Enter, o formulário dispara um submit. O JavaScript escuta com addEventListener e usa preventDefault() para a página não recarregar.
  3. A lista de comandos: um objeto em que cada nome aponta para uma função. help devolve a lista, sobre rola até a seção, e assim por diante.
  4. Executar: o texto digitado vira minúsculo, e o código procura esse nome no objeto. Se acha, roda a função; se não, responde “Comando não encontrado”.
  5. Mostrar a resposta: createElement cria um parágrafo novo, coloca o texto e o append o põe na caixa.
  6. Extras: ↑ e ↓ andam pelo histórico (um array com o que já foi digitado), Tab completa o nome do comando e os segredos achados ficam salvos no localStorage.
const comandos = {
  help: () => "sobre · projetos · contato · jogo",
  whoami: () => "Gabriel Victor · Engenharia de Software",
};

formulario.addEventListener("submit", (evento) => {
  evento.preventDefault();
  const nome = campo.value.trim().toLowerCase();
  const acao = comandos[nome];
  escreve(acao ? acao() : `Comando não encontrado: ${nome}`);
  campo.value = "";
});

Versão resumida. Teste no terminal do portfólio: digite help.

  1. O tabuleiro: um <canvas> de 320 × 320 dividido em 16 × 16 casas de 20 pixels.
  2. A cobra é uma lista: [{x: 8, y: 8}, {x: 7, y: 8}, {x: 6, y: 8}]. A primeira posição é a cabeça.
  3. Andar: a cada passo, a cabeça nova é a cabeça atual mais a direção. Ela entra no começo da lista (unshift) e a última posição sai (pop). Por isso parece que a cobra anda.
  4. Comer: se a cabeça cai na fruta, o código não tira a última posição, e a cobra cresce uma casa. A fruta é sorteada de novo num lugar vazio.
  5. Perder: se a cabeça sai do tabuleiro ou bate no próprio corpo, acaba o jogo e o recorde fica salvo no localStorage.
  6. Controles: setas e WASD (keydown), botões na tela e deslizar o dedo (pointer events) mudam a direção. Virar para trás é bloqueado.
  7. Fluidez: o requestAnimationFrame desenha cerca de 60 vezes por segundo, e entre um passo e outro a cobra é desenhada no meio do caminho.
  8. O bug que achei: a fruta aparecia crescendo, com o tamanho calculado pelo tempo. No celular, a conta às vezes dava negativa, o canvas dava erro e o jogo travava. A correção foi não deixar passar de zero: Math.max(0, ...).
const cabeca = { x: cobra[0].x + dir.x, y: cobra[0].y + dir.y };

O coração do jogo: andar, comer e crescer. Para jogar, digite jogo no terminal.

  1. O problema: cada contrato levava uns 15 minutos para editar o modelo, conferir e imprimir, e são de 10 a 15 por semana.
  2. O pseudocódigo: escrevi o passo a passo em português antes de qualquer código. É ele que está ao lado.
  3. O código: orquestrei o Claude Code para transformar o pseudocódigo em um script em Python, usando os modelos que os advogados já tinham aprovado.
  4. Os testes: rodei com casos reais e conferi campo por campo. Apareceram bugs, como impressora errada e contrato com dado faltando, e por isso o script confere os campos antes de gerar.
  5. A conferência: todo documento passa por uma pessoa antes de ser assinado.
  6. O resultado: de 15 minutos para cerca de 1 minuto por contrato.
PARA cada contrato novo:

  trocar cada marcador ({{NOME}}, {{CPF}}...) pelo dado

  mandar para a impressora certa
